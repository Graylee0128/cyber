# Cyber Range Participant Guide

> 給紅隊與藍隊玩家。你不需要懂平台怎麼做的，這份文件只講你會用到的東西。
>
> 現場工作人員請看 [Operator Guide](../operator-guide/README.md)；
> 想知道系統怎麼運作請看 [Technical Handbook](../technical-handbook/README.md)；
> 常見問題（不確定該去哪找答案時先看這裡）見 [FAQ](../FAQ.md)。

## 1. 演練是什麼

這是一場**紅藍對抗的攻防演練**，不是 CTF，也不是單純的日誌儀表板練習。

- 紅隊實際攻擊一台真的靶機，完成任務目標（Objective）並提交 flag。
- 藍隊在 SOC 畫面上看告警、判讀技法、封鎖來源、結案。
- 全場有一面 **Battleboard** 大螢幕，顯示雙方比分與匿名化的攻防進度。
- 演練結束後會產出一份報告：紅隊打成了什麼、藍隊看到了什麼、有哪些沒看到。

你的每個動作都會被記錄並計分。**分數不是唯一目的**——「攻擊發生了但沒有人看到」這件事
本身就是演練最有價值的產出。

## 2. Red / Blue 的角色

### 🔴 Red Player

你有一台自己的 Kali 終端機（在瀏覽器裡開），和一份任務簡報。你要：

1. 讀 Mission 與 Objective 清單
2. 在終端機裡攻擊目標主機
3. 拿到 flag 後回 Player Portal 提交
4. 卡住時可以買 hint，**但會扣分**

**你看不到藍隊的畫面**，也看不到自己的哪個動作已經被偵測到。這是刻意的。

### 🔵 Blue Player

你有**兩台**終端機（DMZ 與內網各一台），和一個 SOC Console。你要：

1. 在 SOC Console 盯 alert queue
2. 每一則告警：確認接手 → 判讀技法 → 決定是否封鎖來源 → 結案或標記誤報
3. 用兩台終端機做調查與處置

**藍隊不是個人賽。** 你沒有個人 Objective、沒有 hint、沒有 flag——藍隊的計分是團隊層級的
KPI（涵蓋率、平均偵測時間、處置結果），不歸屬到個人。

## 3. 如何加入 Exercise

有兩種入場方式，工作人員會告訴你是哪一種：

| 方式 | 你會拿到什麼 |
|---|---|
| **現場入場** | 現場公布的一組進場碼 |
| **遠端入場** | 一條一次性邀請連結（用過就失效） |

進場後系統會分配一個**座位（Seat）**給你，座位決定你有哪幾台終端機。

> ⚠️ **一條遠端連結只能用一次。** 不要轉發給別人，也不要在多個瀏覽器分頁重複開啟。
> 用掉之後需要工作人員重新簽發。

## 4. 登入 / Seat / Invite Link

流程：

```
拿到進場碼或邀請連結
        ↓
選擇隊伍（Red / Blue）並送出
        ↓
系統分配座位，瀏覽器拿到一張 session cookie
        ↓
工作人員給你 Player Portal 網址（帶終端機代號）
        ↓
開啟畫面，終端機就在頁面上
```

幾件要知道的事：

- **session 在這個瀏覽器上。** 換一台電腦或換瀏覽器（含無痕視窗）等於沒有 session，
  終端機會打不開。要換裝置請找工作人員替你**重新綁定座位**。
- **隊伍滿了會被拒絕。** 如果送出後看到「額滿」，代表該隊座位已分配完，找工作人員。
- **座位是連結網址的一部分。** Player Portal 的網址帶著終端機代號，弄丟就找工作人員要。

## 5. Red Player Portal 使用方式

畫面上有五塊：

| 區塊 | 內容 |
|---|---|
| **Mission** | 任務名稱、難度、預計時長、目標主機 |
| **Objective 清單** | 每個目標的完成狀態（✅ / ⬜） |
| **Hint** | 每個 Objective 下方有「需要提示？（扣 X%）」按鈕 |
| **Shell** | 你的 Kali 終端機，直接在頁面上操作 |
| **提交 Flag** | 選擇 Objective ＋ 填入 flag ＋ 送出 |
| **目前分數** | 你的即時分數 |

**Hint 一定會先問你。** 按下按鈕後會跳出確認視窗，明確寫出這個提示要扣多少分。
**沒有按確認就不會扣分，也不會顯示內容。**

## 6. Blue Player Portal 使用方式

這是你的**任務 HUD**，不是工作台。畫面上有：

| 區塊 | 內容 |
|---|---|
| **Mission** | 任務說明（含「藍隊沒有個人 Objective / Hint / Flag」的說明） |
| **團隊 KPI** | 已結案比例、已封鎖比例、平均偵測秒數 |
| **事件處置概況** | 目前所有事件的處置狀態表 |
| **Shell** | **兩台**終端機：`a` = DMZ、`b` = 內網（flag 所在主機） |
| **團隊分數** | 團隊即時分數 |
| **前往 Blue SOC** | 連到真正的工作台 |

**實際的防守工作在 Blue SOC Console 做，不在這一頁。**

## 7. Blue SOC Console 使用方式

三個分頁：

### 分頁一・事件處置

左邊是 alert queue，點一則 alert 右邊顯示詳情：嚴重度、服務、來源 IP、觸發的規則，
以及對應的**原始 log 片段**。

底下五個動作按鈕：

| 動作 | 說明 |
|---|---|
| **確認接手** | 表示這則告警有人在處理 |
| **判讀技法** | 填入你判斷的攻擊技法。**一次性，送出即鎖定，不能改** |
| **封鎖來源** | 真的會派送封鎖指令到後端。**這不是演戲** |
| **結案** | 處置完成 |
| **誤報** | 標記為 false positive |

兩個重要規則：

- **判讀技法送出前會跳確認視窗**，因為它不可撤銷。重複送出會被拒絕（顯示「目前的狀態
  不允許這個動作」）。
- **封鎖來源如果派送失敗，畫面會明確告訴你「不會計分」**——因為封鎖沒有真的發生。
  看到這個訊息請重試或通報工作人員，不要以為已經擋掉了。

### 分頁二・計分與反應時間

團隊計分表與各事件的反應時間。

### 分頁三・遙測儀表板

嵌入的 Grafana 儀表板，用來看原始遙測趨勢。第一次點開會需要幾秒載入。

## 8. Flag / Hint / Score 規則

### 紅隊

- **Flag**：在 Player Portal 選對應的 Objective，填入 flag 送出。答對顯示 ✅ 並更新分數，
  答錯顯示 ❌，可以再試。
- **Hint**：每個提示有固定的扣分比例，購買前會明確顯示。**同一個 Objective 買多個提示時，
  扣分取最大值，不是累加**——買了第二個更貴的提示，不會在第一個之上再疊一次。
- **分數** = Objective 完成得分 − hint 扣分。

### 藍隊

- 沒有 flag、沒有 hint。
- 團隊計分來自：**動作涵蓋率**（有多少攻擊動作被藍隊處理到）、**偵測延遲**、
  **處置是否真的生效**。
- **封鎖沒有真的派送成功就不計分。** 畫面會告訴你。

## 9. Battleboard 怎麼看

Battleboard 是全場公開的大螢幕，任何人都看得到，**包括對手**。所以它上面的資訊是
刻意消毒過的：

| 你會看到 | 你不會看到 |
|---|---|
| 紅藍總分 | 攻擊的真實技法名稱 |
| 倒數計時 | 「已偵測 3/4」這種分子 |
| `Attack #1`、`Attack #2` 的圓點與狀態 | 哪一個攻擊藍隊還沒發現 |
| Objective 完成比例 | 任何未揭露的答案 |
| 消毒過的即時 timeline | |

**圓點上的 `Attack #N` 不是真的技法編號**，是匿名化的代號。演練結束揭露後才會顯示真名。

如果你是紅隊，想靠盯 Battleboard 判斷「我哪招被抓到了」——看不出來，那是設計好的。

## 10. Exercise 開始 → 結束流程

```
① 工作人員部署平台、建立場次、開放座位
        ↓
② 你入場（進場碼 / 邀請連結）→ 拿到座位
        ↓
③ 開啟 Player Portal，確認終端機能用
        ↓
④ 教官宣布開始 → 倒數計時開始
        ↓
⑤ 紅隊攻擊 / 藍隊防守（本文件 §5–§8）
        ↓
⑥ 時間到，教官結束場次
        ↓
⑦ 揭露：Battleboard 顯示真實攻擊鏈
        ↓
⑧ 講評：紫隊分析哪些攻擊被看到、哪些沒有
```

**重置之後座位與分數會清空**，但稽核紀錄保留。如果教官宣布重置，請等工作人員重新分配座位。

## 11. 常見問題

### Terminal 打不開 / 一片空白

依序檢查：

1. **網址有沒有帶終端機代號？** 沒有的話畫面會顯示「未指定終端機」——跟工作人員要正確網址。
2. **是不是換了瀏覽器或開了無痕視窗？** session cookie 綁在原本那個瀏覽器上。回到原本的
   瀏覽器，或請工作人員替你**重新綁定座位**。
3. **還是空白？** 目前終端機驗證失敗時只會顯示伺服器預設錯誤頁，沒有友善提示——
   看到這種畫面請直接通報工作人員，不要反覆重整。

### Seat 失效

座位可能因為逾時被回收。找工作人員，他們可以在 Event Control 替你**重新綁定**或
**釋出後重新分配**。

### Flag submit 失敗

- **顯示「來源 IP 不在名冊上」**：你的座位沒有被正確登記到本場次名冊。通報工作人員。
- **顯示 ❌**：flag 答錯了，可以再試。
- **顯示「連線失敗，請確認服務是否啟動」**：後端連不上，通報工作人員。

### SOC 沒資料 / alert queue 空的

- 演練還沒開始，或還沒有任何攻擊觸發告警——**這是正常的**。
- 遙測儀表板分頁空白：Grafana 需要獨立啟動，通報工作人員確認。
- 全場都沒資料且持續很久：通報工作人員檢查偵測管線。

### 畫面顯示「找不到對應資料（可能是還沒有進行中的演練）」

場次還沒開始。等教官宣布。

### 畫面顯示「沒有權限」

你打開了不屬於你角色的畫面。回到工作人員給你的網址。

## 12. 禁止事項 / Rules of Engagement

**只准打指定的目標。**

- ✅ 攻擊任務簡報中列出的目標主機
- ⛔ 攻擊演練平台本身（計分、入場、監控等任何後端服務）
- ⛔ 攻擊其他玩家的座位或終端機
- ⛔ 攻擊演練網段以外的任何主機，包含場地網路、講師電腦、網際網路上的任何目標
- ⛔ 嘗試存取不屬於你角色的畫面或網址
- ⛔ 分享、轉發你的邀請連結或 session
- ⛔ 阻斷式攻擊（DDoS、流量洪水、資源耗盡）——平台**沒有針對這類場景驗證過**，
  會影響所有人的演練

**離開演練環境的攻擊行為可能觸法。** 這裡的授權範圍只有這一場演練的指定目標。

發現平台本身的漏洞：**請通報工作人員，不要利用**。那是有價值的回報，但不是這場演練的
計分項目。
